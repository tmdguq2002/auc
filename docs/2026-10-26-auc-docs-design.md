# 안양도시공사 문서작성 스킬 — 설계

작성일: 2026-10-26 · 상태: **승인됨** (2026-10-26)

## 1. 목적과 이유

안양도시공사 직원(팀원 포함)이 claude.ai 웹(및 ChatGPT 웹)에서 메모·PDF·HWPX 자료를 주면,
AI가 부족한 내용을 **질의로 채운 뒤** 공사 서식 그대로의 **HWPX 파일**을 만들어 준다.
한글에서 열어 개인정보 칸만 채우고 바로 기안할 수 있는 수준이 목표다.

## 2. 목표 / 비목표 / 실패 조건

**목표**
- 문서 2종 지원: ① 공문서(시행문) ② 내부 보고서(표지 + 본문)
- 자료를 읽고 부족한 것은 모두 질문: 사실관계(수신자·일시·장소·금액·수량·근거), 내용 방향·어조·강조점까지
- 질문은 한 번에 하나씩, 앞 답을 반영해 이어감 → 마지막에 "이렇게 쓰겠습니다" 요약 확인 → 생성
- 원본 서식과 같은 글꼴·문단·표 모양의 HWPX 생성, 한글에서 정상적으로 열림

**비목표**
- 기안 시스템(온나라 등) 연동, HWP(구형 바이너리) 출력, 공문서·보고서 외 문서(보도자료·계약서 등)
- 사진 삽입(사진대지는 자리만 남김)

**실패 조건 (동작해도 실패로 봄)**
- 개인정보를 묻거나, 자료에 있던 개인정보를 문서에 옮김
- 사용자가 말하지 않은 날짜·수신자·숫자를 지어냄
- 한글에서 안 열리거나 서식이 깨진 파일

## 3. 개인정보 규칙

- 묻지 않는다: 사람 이름, 직통 전화, 이메일 등.
- 자료에 있어도 옮기지 않고 자리표시로 바꾼다: 이름 `○○○`, 전화 `031-389-○○○○`, 이메일 `○○○@auc.or.kr`.
- 결재란(★담당자·팀장·사장 등 **직위**)과 기관 공통 정보(주소 `13918 경기도 안양시 동안구 평촌대로 389`, `www.auc.or.kr`)는 개인정보가 아니므로 유지·질의 대상.
- 보고서 참석자 표의 부서·직급은 유지, 성명만 `○○○`.

## 4. 문서 서식 규칙 (업로드된 실제 문서 기준)

### 4.1 공문서 (예: 풋살장 안전점검 요청)
- 머리: 표어 "존중과 성장의 안양도시공사", 로고, 기관명 / 수신자(·수신자참조) / (경유) / 제목
- 본문: `1.` `2.` `3.` 항목, 합쇼체("~하였습니다", "~하여 주시기 바랍니다")
- 핵심 문구 굵게+밑줄 (어디에 줄지 질의 대상)
- 세부사항은 `<제목>` 박스 + `-` 항목
- 마지막 문장 뒤 두 칸 띄고 `끝.`
- **붙임**: 첨부 여부를 반드시 질의. 있으면 본문 아래 `붙임  1. ○○○ 1부.` 형식(여러 개면 번호 정렬), `끝.`은 마지막 붙임 줄 끝으로 이동
- 꼬리: 발신명의 `안양도시공사사장`, 수신자 목록, 결재란(직위), 협조자, 시행 `부서-번호 (YYYY.MM.DD.)`, 주소·홈페이지, 전화/전송/이메일(자리표시), 공개구분
- 하위 항목 기호가 필요하면 편람 순서 `1.` → `가.` → `1)` → `가)` → `(1)` → `(가)`

### 4.2 내부 보고서 (예: 온실가스 감축 TFT 회의 결과보고)
- 1쪽 표지: 문서번호·결재일자·공개구분 표, 결재·협조란, 큰 제목(남색), 부서명
- 본문 첫 줄: 박스 제목 + 목적 한 문장("~하고자 함.")
- 대제목 로마숫자 `Ⅰ Ⅱ Ⅲ …` + 제목
- 항목 체계 `1.` → `○`(원본은 기호 글꼴 문자 U+F06D) → `-` → `※`
- 개조식 명사형 종결("~공유", "~논의", "~추진", "~함.")
- 표 지원(참석자 표, 관리대장(안) 같은 일반 표), 사진대지는 제목+빈 칸

## 5. 접근 방식 (검토 결과)

| 안 | 내용 | 장단점 |
|---|---|---|
| **A. 서식 파일 + 생성 스크립트 (선택)** | 업로드 문서에서 본문을 비운 서식을 스킬에 포함, AI는 구조화된 내용(JSON)을 쓰고 스크립트가 원본 문단·글자 모양 ID로 채워 HWPX 생성 | 결과 일관·원본과 동일한 모양 / 스크립트가 지원하는 요소만 가능 |
| B. 매번 XML 직접 편집 | 서식만 두고 AI가 XML 수정 | 유연함 / 품질 들쭉날쭉, 깨진 파일 위험 |
| C. 서식 없이 새로 생성 | — | 공사 서식과 달라져 제외 |

사용자가 A를 선택함. 이유: 질의는 스킬이, 서식은 스크립트가 담당해 역할이 분리됨.

## 6. 결정된 사항

- 산출물: claude.ai에 업로드할 **스킬 ZIP** (Agent Skills 표준: `SKILL.md` + `scripts/` + `templates/` + 참고문서)
- 스크립트는 **Python 표준 라이브러리만** 사용(zipfile, xml) — claude.ai·ChatGPT 샌드박스 모두에서 설치 없이 실행
- 스킬 작성은 superpowers `writing-skills` 방식: 스킬 없이 기준선 테스트 → 실패 기록 → 스킬 작성 → 재테스트 → 허점 보완
- ChatGPT: 같은 ZIP 사용을 팀이 직접 확인. 안 되면 대안으로 커스텀 GPT(지침 + 파일 첨부)
- 사용 언어: 질의·문서 모두 한국어

## 7. 구조(안)

```
auc-docs/
  SKILL.md                    # 언제 쓰는지 + 질의 절차 + 개인정보 규칙
  reference/gongmun.md        # 공문서 작성 규칙·예시
  reference/report.md         # 보고서 작성 규칙·예시
  templates/gongmun.hwpx      # 본문 비운 공문 서식
  templates/report.hwpx       # 본문 비운 보고서 서식
  scripts/build_hwpx.py       # JSON → HWPX
  scripts/check_privacy.py    # 결과물 개인정보 패턴 검사(전화·이메일·이름 칸)
```

## 8. 검증 방법

- 생성 HWPX: ZIP/XML 구조 검사, 원본과 같은 스타일 ID 사용 여부, 미리보기 텍스트 확인
- 한글에서 실제로 열리는지는 **사용자 확인 필요**(이 환경엔 한글 없음)
- 행동 테스트(서브에이전트): ① 메모 한 줄 → 질문을 하나씩 하는지 ② 개인정보 묻지 않는지 ③ 자료 속 이름을 자리표시로 바꾸는지 ④ 날짜 등을 지어내지 않는지 ⑤ 요약 확인 후 생성하는지

## 9. 빌더에게 맡기는 부분

- JSON 스키마 세부 형태, 스크립트 내부 구현
- 서식 비우기 방법(원본에서 본문 문단 제거, 로고·결재란 유지)
- 원본 문서의 실제 내용(시행번호·담당자 이메일 등)은 서식에서 지우고 자리표시로 교체
