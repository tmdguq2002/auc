# 안양도시공사 문서작성 (요지·공문서·보고서 → HWPX)

자료(메모·PDF·HWPX·회의록)를 받아 **질문으로 빈 곳을 채운 뒤** 공사 서식 그대로의 HWPX를 만든다.
사용자는 한글에서 열어 개인정보 칸만 채우고 바로 기안한다.

## 절차

1. **첫 질문은 항상 문서 종류다.** 자료를 끝까지 읽은 뒤, 다른 어떤 질문보다 먼저 묻는다:
   > 어떤 문서로 만들까요? **① 요지**(한 장 요약) / **② 공문서**(시행문) / **③ 보고서**(표지+본문)

   요청에 "공문"처럼 종류가 적혀 있어도 묻는다. 그때는 그 종류를 추천으로 표시한다("②로 하시려는 것 같은데 맞나요?").
   "질문하지 말고 바로"라고 해도 종류가 요청에 없으면 이 질문 하나는 한다(종류가 있으면 그대로 진행).
   답을 받으면 그 규칙을 읽는다: 요지 `reference/yoji.md`, 공문 `reference/gongmun.md`,
   보고서 `reference/report.md`(A형)·`reference/report_b.md`(B형).
   - **모양은 묻지 않고 직접 고른다.** 고른 모양과 이유는 요약 확인(4단계)과 "제가 정한 부분"에 적는다.
     | 문서 | 이렇게 고른다 |
     |---|---|
     | 보고서 | 타 기관과의 협의회·대외 회의 결과이거나 안건이 둘 이상이면 **B형**(□ 체계·남색 대제목·요약 상자), 그 밖의 내부 회의·계획 보고는 **A형**(○ 체계·보라 대제목) |
     | 공문 발신명의 | 부서가 공사 안 부서들에 자료 제출·회신·안내를 요청하면 **부서장 명의**(예: 전략기획부장), 공사 밖 기관이 수신하거나 점검·지시처럼 공사 차원의 시행이면 **사장 명의**(안양도시공사사장) |
     | 요지 | 표로 정리할 내용(법령·사례·현황)이 있으면 표 위주, 없으면 글 위주 — 스크립트가 표 유무로 자동 선택 |

     사용자가 모양을 직접 말하면 그대로 따른다.
2. **질문한다 — 한 번에 하나씩.** 각 reference의 "질문으로 확정할 것" 표에서 자료로 답이 안 되는 것을
   중요한 순서대로 묻는다. 질문은 한 문장, 왜 묻는지 짧게, 가능하면 초안을 제안하고 확인받는다.
   앞 답을 반영해 다음 질문을 고른다. 사실관계뿐 아니라 어조·강조·구성도 묻는다.
3. **붙임(첨부)은 공문마다 반드시 묻는다.** 사용자가 말한 붙임만 넣는다.
4. **요약 확인.** "이렇게 쓰겠습니다"로 **고른 모양(보고서 A/B형·발신명의)**·제목·수신·항목 요지·붙임·결재선을 짧게 보여 주고 확인받는다. 사용자가 모양을 바꾸라고 하면 바꾼다.
5. **JSON 작성 → 생성 → 검사:**
   ```bash
   python3 scripts/build_hwpx.py 내용.json 결과.hwpx
   python3 scripts/check_privacy.py 결과.hwpx
   ```
   검사에 걸리면 자리표시로 고쳐 다시 만든다. (스크립트 경로는 이 스킬 폴더 기준)
6. **전달.** HWPX 파일과 함께 "제가 정한 부분"(문구 선택, 기호 배치 등)과 "한글에서 채울 칸"(이름·전화·이메일·문서번호·시행일자) 목록을 준다.

## 지어내지 않는다

자료나 사용자 답에 없는 **사실**은 쓰지 않는다: 날짜·기한·시간, 수신 부서, 붙임, 관련 근거(법령·문서번호),
수치, 요구사항, 회의 결정사항. 모르면 질문하고, 끝내 모르면 `○○`로 남기고 전달 목록에 적는다.
문장 다듬기와 개조식 변환은 해도 되지만 **내용을 보태지 않는다.**

## 개인정보

- **묻지 않는다:** 사람 이름, 전화, 휴대폰, 이메일. 사용자가 알려 주겠다고 해도 받지 않고
  "한글에서 직접 채우시면 됩니다"라고 안내한다(서식에 자리표시가 이미 있음).
- **자료에 있어도 옮기지 않는다:** 이름 `○○○`, 전화 `031-389-○○○○`, 이메일 `○○○@auc.or.kr`.
  참석자 표는 부서·직급만 쓰고 성명은 `○○○`.
- 직위(★담당자, 안전감사팀장, 사장)와 부서명은 개인정보가 아니므로 쓴다.

## "질문하지 말고 바로 써줘"라고 하면

어조·구성 질문은 생략하고 바로 만든다. 그래도 사실은 지어내지 않는다: 모르는 날짜·수신·붙임은 `○○`로 두고
붙임은 넣지 않으며, 전달할 때 "채워야 할 칸" 목록을 맨 위에 준다.

## 합리화 차단

| 이런 생각이 들면 | 실제로는 |
|---|---|
| "빈칸을 [ ]로 표시하면 되니 질문은 생략" | 빈칸 수십 개를 떠넘기는 것. 먼저 질문한다. |
| "공문엔 보통 점검표가 붙으니 붙임 넣자" | 붙임은 사용자가 말한 것만. 묻는다. |
| "관련 법령을 근거로 넣으면 그럴듯하다" | 근거는 사용자가 준 것만. |
| "실명은 공문이 아니라 내부 보고서니 괜찮다" | 내부 보고서도 자리표시. |
| "본인이 번호를 알려 주겠다니 받아서 넣자" | 받지 않는다. 한글에서 직접 채우게 안내. |
| "※ 문구 하나 덧붙이고 각주로 알리면 된다" | 지어낸 내용은 안 쓴다. |
| "마크다운으로 보여 주면 붙여넣으면 된다" | 결과물은 서식 HWPX. 본문 미리보기는 요약 확인 단계에서만. |
| "질문 여러 개를 한 번에 물으면 빠르다" | 한 번에 하나. 답에 따라 다음 질문이 바뀐다. |
