# 내부 보고서 작성 규칙

안양도시공사 보고서 서식(`templates/report.hwpx`: 표지 + 본문)에 들어갈 내용을 JSON으로 쓰는 법.

## 질문으로 확정할 것 (자료에 없으면 반드시 묻기)

| 항목 | 예시 질문 |
|---|---|
| 보고 목적 | "이 보고로 무엇을 결정·공유하려는 건가요?" → `purpose` 한 문장 |
| 기안 부서 | `dept`, `doc_no` 의 부서명 |
| 결재선 | 직위만(최대 4칸), 협조 직위(최대 6칸) |
| 대제목 구성 | 제안 후 확인: 결과보고 `회의개요/주요 논의결과/추진방향/향후계획`, 계획보고 `추진배경/현황/추진계획/소요예산/향후계획` |
| 사실관계 | 일시·장소·대상·수치·일정. 자료에 없으면 지어내지 않고 질문 |
| 표 | 참석자·현황·일정 등 표로 정리할지 |
| 사진대지 | 넣을지, 사진 설명 문구 |
| 강조 | 굵게 할 핵심 문구 |
| 공개구분 | 공개 / 부분공개 / 비공개 |

**묻지 않는 것:** 사람 이름·전화·이메일. 자료에 있어도 옮기지 않는다. 참석자 표는 부서·직급만 쓰고 성명은 `○○○`.

## 문체 (개조식)

- 명사형으로 끝낸다: "~공유", "~논의", "~추진", "~검토", "~필요성에 공감".
- 목적 문장만 "~하고자 함."
- 한 항목은 한 가지 내용, 두 줄을 넘기지 않게.
- `num` 소제목 아래 `circle` 은 소제목을 되풀이하지 않는다. 내용이 한 줄뿐이면 소제목 없이 `circle` 만 쓴다.
- 날짜 `2026. 10. 22.(목)`, 기간 `2026. 11.~2027. 1.`, 연도 약칭 `'27년` 또는 `27년`.

## 기호 체계 (스크립트가 붙임)

| 블록 | 결과 | 용도 |
|---|---|---|
| 섹션 `title` | `Ⅰ 회의개요` (Ⅰ~Ⅹ 자동) | 대제목 |
| `num` | ` 1. 소제목` (섹션마다 1부터) | 중제목 |
| `circle` | ` ○ 내용` | 주요 항목 |
| `circle` + `when` | ` ○ 내용 ········· 2026.11월` | 일정(향후계획) |
| `dash` | `  - 내용` | 세부 항목 |
| `note` | `※ 내용` | 참고·단서 |
| `table` | 표 (머리행 + 행) | 참석자·현황 |
| `photo` | 빈 사진 칸 4개 + 설명 | 사진대지 |

`circle`(일정 포함)·`dash`·`num`은 문자열 또는 `[문구, 강조여부]` 목록. 강조=굵게.

## JSON

```json
{"type": "report",
 "doc_no": "전략기획부-○○", "date": "", "disclosure": "공개",
 "approvers": ["★담당자", "전략기획부장"], "cooperators": [],
 "dept": "전략기획부",
 "title": "온실가스 감축 TFT 회의 결과보고",
 "purpose": "온실가스 감축 TFT 1차 회의 결과를 보고하고, 논의사항을 바탕으로 에너지 절감활동을 추진하고자 함.",
 "sections": [
  {"title": "회의개요", "blocks": [
    {"circle": "일    시 : 2026. 10. 22.(목) 14:00"},
    {"circle": "장    소 : 공사 대회의실"},
    {"table": {"header": ["부 서", "직 급", "성 명"], "rows": [["전략기획부", "일반6급", "○○○"]]}}]},
  {"title": "주요 논의결과", "blocks": [
    {"num": "에너지 사용 관리대장 시범운영"},
    {"circle": [["2026년 11월부터", true], [" 목표관리 대상시설 시범운영", false]]},
    {"dash": "전년 동월 대비 증감 원인 분석"},
    {"note": "시설 운영 및 이용객 안전에 지장이 없는 범위에서 추진"}]},
  {"title": "향후계획", "blocks": [
    {"circle": "관리대장 시범운영", "when": "2026.11월"}]}
 ]}
```

- `doc_no` 번호와 `date`(결재일자)는 기안 시스템이 정하므로 `○○`와 빈칸으로 둔다.
- 필수: `title`, `dept`, `purpose`, `sections`.
- 표의 모든 행은 머리행과 열 수가 같아야 한다. 열 너비는 내용 길이에 비례해 자동으로 나뉜다(한글에서 조정 가능).
