# 공문서(시행문) 작성 규칙

안양도시공사 시행문 서식(`templates/gongmun.hwpx`)에 들어갈 내용을 JSON으로 쓰는 법.

## 질문으로 확정할 것 (자료에 없으면 반드시 묻기)

| 항목 | 예시 질문 |
|---|---|
| 발신 부서 | "어느 팀(부) 명의로 나가나요?" → `doc_no` 의 부서명 |
| **발신명의** | "**사장 명의**(안양도시공사사장)로 나가나요, **부서장 명의**(예: 전략기획부장)로 나가나요?" → `sender` — 항상 묻기. 공사 밖·여러 부서에 지시하는 시행문은 보통 사장 명의, 부서가 전 부서에 자료를 요청하는 내부 공문은 부서장 명의 |
| 수신 | "수신은 어디인가요? 여러 곳이면 '수신자참조'로 하고 아래 수신자 목록에 넣겠습니다." |
| 경유 | 보통 없음. 있다고 하면 기재 |
| 제목 | 초안을 제안하고 확인 받기 |
| 본문 사실관계 | 일시·장소·대상·기한·금액·근거(관련 문서번호) |
| 요청 강도·어조 | "철저히 이행" 같은 강한 요청인지, "협조 부탁" 정도인지 |
| 강조(굵게+밑줄) | 어느 문구를 강조할지 제안 후 확인 |
| 박스 | 세부 목록을 `<제목>` 박스로 묶을지 |
| **붙임** | "첨부할 문서가 있나요? 있으면 이름을 알려 주세요." — 항상 묻기 |
| 결재선 | 직위만: "★담당자 / 팀장 / 사장" 처럼(최대 4칸) |
| 협조 | 협조 부서 직위(최대 3칸) |
| 공개구분 | 공개 / 부분공개 / 비공개 |

**묻지 않는 것:** 담당자 이름, 전화번호, 이메일. 서식에 `031-389-○○○○`, `○○○@auc.or.kr` 로 이미 들어 있다.

## 문체

- 합쇼체: "~하였습니다", "~하여 주시기 바랍니다", "~하오니 ~협조하여 주시기 바랍니다".
- 첫 항목은 배경(관련 근거·발생 사실), 다음 항목은 요청, 마지막은 부가 요청·협조.
- 내용이 짧으면 **한 문단**으로 쓴다(예: "예산법무과-○○(2026. 8. 14.)호와 관련하여 … 9. 14.(월)까지 제출하여 주시기 바랍니다."). 본문이 한 항목뿐이면 스크립트가 `1.`을 붙이지 않는다.
- 관련 문서가 있으면 첫 항목: "관련: 안전감사팀-85(2026. 1. 5.)" 형식.
- 날짜 `2026. 11. 12.(목)`, 시간 `14:00`, 금액 `금1,000,000원(금일백만원)`.
- 쌍점 앞은 붙이고 뒤는 한 칸: `일시: 2026. 11. 12.`

## 항목 기호

번호는 스크립트가 붙인다. 본문 블록마다 `1.` `2.` …, 하위(`sub`)는 `가.` → `1)` → `가)` → `(1)` → `(가)`.
본문 블록이 하나뿐이고 하위 항목이 없으면 번호 없이 한 문단(내어쓰기 없음)으로 만든다.

## 끝 표시

스크립트가 처리한다: 마지막 문장(붙임이 있으면 마지막 붙임) 뒤 두 칸 + `끝.`

## JSON

```json
{"type": "gongmun",
 "receiver": "수신자참조", "via": "",
 "title": "풋살장 안전사고 발생 관련 안전점검 실시 요청",
 "body": [
  {"text": [["최근 풋살 강습 중 인조잔디 바닥에 박혀있던 못에 경상을 입은 사고가 발생하였습니다.", false]]},
  {"text": [["이에 따라, ", false], ["유사 사고 방지를 위하여 다음과 같이 안전점검을 철저히 이행", true], ["하여 주시기 바랍니다.", false]],
   "sub": [{"text": [["점검기간: 2026. 1. 12.~1. 16.", false]]}]},
  {"box": {"title": "주요 점검 사항", "items": ["인조잔디구장 전체 구역 돌출 못 등 위험요소 정밀 점검", "발견된 위험 요소에 대한 즉시 안전 조치"]}},
  {"text": [["아울러, 각 부서에서는 점검 시 적극 협조하여 주시기 바랍니다.", false]]}
 ],
 "attachments": ["안전점검표"],
 "receivers": ["종합운동장사업부장", "동안체육사업부장", "만안체육사업부장"],
 "approvers": ["★담당자", "안전감사팀장", "사장"],
 "cooperators": [],
 "sender": "안양도시공사사장",
 "doc_no": "안전감사팀-○○", "date": "", "disclosure": "공개"}
```

- `text`: 문자열, 또는 `[문구, 강조여부]` 목록. 강조=굵게+밑줄. 박스 `items`의 각 항목도 같은 형식.
- 필수: `title`, `body`. 하위(`sub`)는 5단계, 단계마다 14개(가~하)까지.
- `attachments`: 이름만 쓰면 ` 1부.`가 붙는다. 부수가 다르면 `"점검표 2부"`처럼 적는다.
- `receiver`: 한 곳이면 그 기관·직위, 여러 곳이면 `"수신자참조"` + `receivers` 목록. 전 부서면 `receivers: ["全 부서"]`.
- `sender`: 발신명의. 기본 `안양도시공사사장`, 부서장 명의면 `"전략기획부장"`처럼.
- `doc_no` 번호와 `date`(시행일자)는 기안 시스템이 정하므로 `○○`와 빈칸으로 둔다.
- 박스는 본문 첫 항목이 될 수 없다.
